# Remedy 의료 청구 에이전트

*Claude가 번역했습니다. 원어민 검토는 아직 진행되지 않았습니다. 영어 [README](README.md)가 기준입니다.*

의료 청구(미국 의료 체계의 수익 주기)를 위한 작은 MCP 에이전트 30개입니다. 각 에이전트는 **한 가지 업무**만 맡습니다. 예를 들어 발송 전 청구 점검, 835 파일의 지급 거절을 원인별로 정리, 과소 지급된 항목 찾기, 환자 대변 잔액 보고서 처리 등이며, 그 범위를 벗어나 행동할 수 없습니다. 진료 관리 시스템, 클리어링하우스, 지급자 포털에서 이미 내보내는 파일(837, 835, 999, 277CA, 271, 278 또는 스프레드시트)을 읽고, 결과가 AI 모델에 닿기 전에 환자 식별자를 가리며, 작업 목록을 사용자의 컴퓨터에 기록하고, 무엇이든 발송, 환불, 전기 또는 지급하기 전에 이름이 확인된 담당자를 기다립니다.

MIT 라이선스 · Node 20 이상 · 로컬 파일만 · 자격 증명 없음 · 의존성 없음 · 가상의 테스트 데이터만 사용

## 사용해 보기

```bash
npx -y sage-of-claims demo          # 가상 데이터로 청구 점검
npx -y yarrow-of-denials demo       # 가상의 835로 지급 거절 작업 목록 만들기
```

각 에이전트에는 가상 파일로 실행되는 `demo`, 자체 테스트 케이스로 확인하는 `eval`, 그리고 Claude Desktop, Claude Code, Cursor 등 MCP 호스트용 MCP 서버(`npx -y <agent> mcp --root <폴더>`)가 있습니다. 열 이름은 한국어로도 인식되며, `--lang ko`로 HTML 보고서를 한국어로 받을 수 있습니다.

## 에이전트 목록

**청구를 보내기 전:** `marjoram-of-registration`(환자 등록과 보험 정보), `basil-of-eligibility`(271 자격 응답), `mint-of-authorizations`(사전 승인과 278), `borage-of-estimates`(무보험 환자를 위한 선의의 견적), `clover-of-charges`(청구가 누락된 진료), `sage-of-claims`(청구 점검), `dill-of-modifiers`(수정자), `ginger-of-edits`(CMS가 공개한 NCCI 편집 규칙), `anise-of-dental`(치과), `caraway-of-anesthesia`(마취 단위), `cumin-of-dme`(의료 장비와 임대), `tarragon-of-labs`(검사, CLIA), `lovage-of-telehealth`(원격 진료), `nettle-of-audits`(코딩 감사).

**청구를 보낸 후:** `verbena-of-rejects`(999와 277CA 반려), `chamomile-of-ar`(미수금과 제출 기한), `fennel-of-remits`(835와 은행 입금 대조), `yarrow-of-denials`(원인별 지급 거절), `rosemary-of-appeals`(이의 신청 초안), `thyme-of-underpayments`(계약 대비 과소 지급), `tansy-of-credits`(대변 잔액과 환불), `aloe-of-statements`(환자 청구서), `savory-of-plans`(분할 납부 계획).

**진료소 운영:** `hyssop-of-fees`(수가표와 Medicare 비교), `laurel-of-contracts`(지급자 계약), `sorrel-of-payers`(지급자별 성적표), `lavender-of-credentialing`(자격 인증과 만료일), `angelica-of-prices`(병원 가격 투명성 파일), `mallow-of-kpis`(자체 목표 대비 지표), `vervain-of-onboarding`(새 진료소 가동 준비).

## 환자 데이터

결과는 AI 모델로 전달되므로 각 에이전트는 먼저 환자 식별자를 가립니다(`--phi mask`, 기본값). 이름, 가입자 번호, 차트 번호는 고정된 가명(`PT-3f9a1c2e`)이 되고, 생년월일은 출생 연도가 되며, 주소, 전화번호, 이메일, 사회보장번호는 자유 텍스트 안에서도 삭제됩니다. 디스크에 저장되는 보고서 파일에는 실제 이름이 남습니다. 이는 PHI를 모델로부터 떼어 두는 설계이며 HIPAA 준수 판정이 아닙니다. 업무 제휴 계약(BAA)과 내부 정책은 계속 적용됩니다.

## 안전 장치

- **에이전트별 허용 목록.** 각 에이전트는 자신의 도구만 호출할 수 있습니다.
- **거부되는 도구.** 청구 제출, 지급 전기, 환불 실행, 지급자 포털 로그인은 이름을 지정해 차단됩니다.
- **이름이 있는 한 번의 클릭.** 청구서, 이의 신청, 환불 요청, 학습한 규칙의 채택은 Auto 모드에서도 이름이 확인된 담당자를 기다립니다.
- **조이기만 하는 기억.** 학습한 규칙은 담당자가 승인한 뒤에만 적용되며 점검을 추가할 수만 있습니다.
- **감사 로그**는 `.remedy/`에 해시로 연결되어 저장되고, 설정하면 Ed25519로 서명됩니다. **긴급 정지:** `<agent> kill`.

## 테스트 방법

각 에이전트에는 자체 테스트, 모든 에이전트에 공통인 계약 테스트(테스트 데이터의 환자 식별자가 어떤 결과에도 나타나지 않는지 포함), 가상 파일을 사용하는 8~13개의 테스트 케이스가 있습니다. 스프레드시트를 쓰는 모든 케이스는 독일, 프랑스, 스페인, 브라질, 이탈리아, 일본, 중국, 한국의 내보내기 형식으로 다시 실행되며, 각 에이전트의 파일에 악의적인 데이터를 심어 검사합니다. [REVIEW-ver1.md](REVIEW-ver1.md)(영어)에 모든 점검 항목이 있습니다.

## 한계

- 각 에이전트는 사용자가 준 파일로만 작동하며 지급자, 클리어링하우스, 진료 관리 시스템, 은행에 로그인하지 않습니다.
- 코드표, 지급자 규칙, 수가표는 불러온 내용만큼만 최신입니다. 내장된 예시 규칙은 어떤 지급자의 정책도 아닙니다.
- 코딩, 법률, 규정 준수, 의료에 관한 조언이 아닙니다. 결정하고 행동하는 것은 사람입니다.
